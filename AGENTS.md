# Locale Admin

Admin application for managing translations in **projects**. This file is the entry point for every AI agent and tool working in this repo. Module rules live in the module's own `AGENTS.md`; step-by-step procedures live in skills.

Current plan: [`docs/plans/project-roles.md`](docs/plans/project-roles.md) (approved 2026-10-25, milestone 1 done). ## Domain

| Term            | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Member          | A user with global role `USER` ("Používateľ" in the UI). Sees and works only in the projects they are a member of. Created by an `ADMIN` on `/admin/users` with an internal password; there are no invitations and no organizations.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Project         | One translation sheet (e.g. B2B admin, B2C iOS, B2C Android, web URLs). Listed on the index page `/`; settings and members under `/projects/$projectId`. Only an `ADMIN` creates projects.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Project member  | A user in a project (`ProjectMember`). Only an `ADMIN` adds existing users to a project and removes them, a member sees the list and can leave (the last one too). An `ADMIN` is never a member (409 `MEMBER_IS_ADMIN`; becoming `ADMIN` drops the memberships) and works in every project.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Editor          | A person who edits translations in projects.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Global role     | `ADMIN` (sees every project without a membership, manages users, projects and project members) or `USER` (works only in the projects they are a member of, with the role of that membership). Stored on `User.role`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Language        | Translation language of a project (`ProjectLanguage`) from a fixed catalog (`SUPPORTED_LANGUAGES`). Each project has exactly one base language.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Translation key | A key in one version of a project (`TranslationKey`), unique per version + namespace + name, at most 2 000 UTF-8 bytes (`IMPORT_KEY_MAX_BYTES`). Path-like keys (`orders.empty.title`) are grouped by prefix; keys with spaces are sentences and are never split on dots. Created by an import or by hand into an existing namespace of a version that already has an import (`ADMIN`, „Pridať kľúč“, 409 `PROJECT_VERSION_EMPTY` otherwise). Every member can export one version (CSV, XLSX), optionally only its diff (`diffOnly`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Namespace       | Name of the source JSON file of a key (`loc`, `paths`, …; CSV section `--loc--`), at most 100 characters. Must be preserved exactly for export.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Translation     | Value of a key in one project language (`Translation`). `null` or a missing row = untranslated; `""` is stored as `null`; the status (Preložené / Nepreložené) is derived from the value and never stored. A key (row) is translated only when every project language has a value (extended view); the compact view judges by the target language. Edited in the modal „Upraviť preklad“ opened from a cell.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Import          | Two-step CSV import into a version, `ADMIN` only (`POST …/imports/preview`, then `POST …/imports` with the same file, a column → language mapping and the `versionId`). The file defines the key set of the version: keys only the previous version has are copied with every language first, new keys are created, keys of the version missing from the file are removed; a filled value overwrites, an empty one never clears a translation. The preview reports `copiedFromPrevious`, `previousVersion` and `removed`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Version         | A named date window of a project (`ProjectVersion`) matching a release of the code (`v2.45`): `startsAt` = developers deliver the keys (code freeze), `endsAt` = editors finish the translations. **Every version owns its own copy of the keys and cells for all languages** (`TranslationKey.versionId`, unique per version + namespace + name); a version is created empty and filled by an import, which copies the keys of the nearest older version (by `startsAt`) and defines the key set (keys missing from the file are removed). Writes never spread to other versions. The translations list, export, dashboard and daily activity read one version (`versionId` required, the current one by default); `?diff=true` and `GET …/versions/:id/diff` compare a version with the previous one (added, changed, removed). An `EDITOR` is locked outside the window and when locked by hand (409 `PROJECT_VERSION_LOCKED`), an `ADMIN` writes always and can delete a non-current version with its keys (409 `PROJECT_VERSION_CURRENT`). Plan `docs/plans/version-snapshots.md`, ADR 0007. |
| Project role    | `MANAGER` ("Správca": the rights of an `ADMIN` in the project, no `/admin/*`, cannot create projects nor add, remove or change members), `EDITOR` (translates) or `VISITOR` (only reads, filters and exports translations) on the membership (`ProjectMember.role`, default `EDITOR`), set by an `ADMIN` per project; one user can have a different role in each project. The API exposes it as `myRole` of a project. Plan `docs/plans/project-roles.md`, ADR 0008.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

There is no self-registration. An `ADMIN` creates every user (admin or member) on `/admin/users` and adds existing users to projects on the Members page of a project.

| `pnpm dev`                                                           | FE (`:5173`) + BE (`:4000`) locally with hot reload. Needs `pnpm db:up`             |
| `pnpm db:up` / `db:down`                                             | Postgres in Docker                                                                  |
| `pnpm db:migrate` / `db:seed` / `db:reset`                           | Prisma migrate dev + seed / seed only / drop, migrate, seed                         |

| `pnpm lint` / `typecheck` / `test` / `test:integration` / `test:e2e` | checks                                                                              |

## Hard rules

1. Never commit secrets. Real values only in `.env` (gitignored). `.env.example` holds local-only values.
2. FE and BE contracts (request/response, error codes, validation) live only in `packages/shared`. Never duplicate a schema.
3. API errors use the contract `{ error: { code, message, details? } }`. FE shows only translated `code`, never `message`.
4. Every user-facing text goes through i18n (`sk` default, `en`). No hardcoded strings in components.
5. Never change files outside your role's ownership (see `.agents/agents/`). Ask the orchestrator in the handoff report instead.
6. Never touch the reference project `~/REPOS/Notino-Landing-Monorepo` except for reading.
7. Verify current library docs (Context7 or official docs) before using an API you have not used in this repo yet.
8. When something is unclear or contradicts the plan, stop and ask. Do not guess silently.
9. Update `docs/` in the same step as the code change (skill `docs-update`).
10. Commits follow Conventional Commits (skill `commit-messages`). The remote is `origin` (GitHub `michal-bella/Locale-Admin`). Push `main` only when the user asks; never push agent branches.
11. Supported OS: macOS and Linux only.
