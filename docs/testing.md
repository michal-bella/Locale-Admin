# Testovanie

Unit testy (Vitest, vo frontende Vite+), integračné testy backendu (Vitest + supertest voči test DB `locale_test`) a E2E testy (Playwright voči produkčnému Docker stacku).

## Druhy testov

| Druh            | Kde                                | Nástroj                                           | Príkaz (z rootu)                    |
| --------------- | ---------------------------------- | ------------------------------------------------- | ----------------------------------- |
| Unit (shared)   | `packages/shared/src/**/*.test.ts` | Vitest                                            | `pnpm --filter @locale/shared test` |
| Unit (backend)  | `backend/src/**/*.test.ts`         | Vitest, bez DB                                    | `pnpm --filter backend test`        |
| Unit (frontend) | `frontend/src/**/*.test.ts(x)`     | Vite+ (`vp test`, jsdom, Testing Library)         | `pnpm --filter frontend test`       |
| Integračné (BE) | `backend/test/**/*.test.ts`        | Vitest + supertest, reálny Postgres `locale_test` | `pnpm test:integration`             |
| E2E / smoke     | `e2e/`                             | Playwright voči `http://localhost:8080`           | `pnpm test:e2e`                     |

## Súhrnné príkazy

| Príkaz                  | Čo spustí                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------- |
| `pnpm test`             | všetky unit testy (shared, backend, frontend)                                                 |
| `pnpm test:integration` | integračné testy backendu                                                                     |
| `pnpm verify`           | lint, typecheck, secretlint, unit testy a integračné testy; musí prejsť pred dokončením kroku |
| `pnpm test:e2e`         | E2E testy voči Docker stacku (Chromium a WebKit), nie je súčasťou `pnpm verify`               |

## Integračné testy backendu

Potrebujú bežiaci Postgres (`pnpm db:up`) a `TEST_DATABASE_URL` v `.env`.

- `globalSetup` overí, že názov DB končí na `_test` (inak testy okamžite skončia), nastaví `DATABASE_URL` na test DB (testy tak nikdy nepoužijú dev DB), DB vytvorí, ak neexistuje, a aplikuje migrácie (`prisma migrate deploy`).
- Pred každým testom sa vyprázdnia všetky tabuľky okrem `_prisma_migrations` (`TRUNCATE ... RESTART IDENTITY CASCADE`, zoznam z `pg_tables`).
- Súbory bežia sériovo (`fileParallelism: false`), lebo zdieľajú jednu DB.
- Testy nepoužívajú seed. Dáta si vytvárajú cez helpery v `backend/test/helpers/` (`createUser({ role })`, `createTestApp({ config, prisma })`).

## Unit testy frontendu

- Prostredie jsdom, setup v `frontend/src/test/setup.ts` (jest-dom matchery, i18n).
- Stránky sa renderujú cez router s pamäťovou históriou, keď záleží na routingu.
- `src/lib/i18n.test.ts` overuje, že každý `ERROR_CODE` a `VALIDATION_CODE` má preklad `sk` aj `en`. Nový kód bez prekladov test zhodí.

## E2E testy (Playwright)

Testy sú v `e2e/tests/`, pomocné moduly v `e2e/support/`, konfigurácia v `e2e/playwright.config.ts`. Bežia v prehliadačoch Chromium a WebKit voči produkčnému stacku na `http://localhost:8080`.

### Prvé spustenie

Prehliadače Playwrightu sa inštalujú zvlášť (raz na stroj, po zmene verzie `@playwright/test` znova):

```bash
pnpm --filter e2e exec playwright install chromium webkit
```

Potrebný je `.env` v roote (`SEED_ADMIN_PASSWORD`, `DATABASE_URL`) a admin zo seedu v lokálnej DB (`pnpm db:seed`).

### Spustenie

```bash
pnpm test:e2e                          # stack + všetky testy
pnpm test:e2e tests/login.spec.ts      # iba jeden súbor (argumenty idú do Playwrightu)
pnpm test:e2e --project=webkit         # iba jeden prehliadač
```

`pnpm test:e2e` (skript `scripts/test-e2e.sh`) najprv spustí Postgres, ak nebeží (`docker compose up -d --wait db`, bežiaci kontajner nereštartuje), potom znova vytvorí kontajnery `backend` a `frontend` (`docker compose up -d --build --wait --force-recreate --no-deps`) s `LOGIN_RATE_LIMIT_MAX=1000`, aby testy neskončili na 429, a potom spustí `pnpm --filter e2e test:e2e` (`playwright test`). Stack po testoch beží ďalej s limitom 1000; `pnpm stack:up` vráti hodnoty z `.env`.

Testy sa dajú pustiť aj priamo (`pnpm --filter e2e test:e2e`) proti už bežiacemu stacku. Jeden beh urobí približne 17 pokusov o prihlásenie (setup 2, na prehliadač 4 v `login.spec`, 1 v `users.spec` a 2 v `profile.spec`, 1 v `api-smoke.spec` iba v Chromiu), teda viac ako predvolený limit 10 za 15 minút. Priamy beh preto potrebuje zvýšený `LOGIN_RATE_LIMIT_MAX`; inak použite `pnpm test:e2e`.

Iná adresa aplikácie (napr. dev mód počas písania testov) cez `E2E_BASE_URL`:

```bash
E2E_BASE_URL=http://localhost:5173 pnpm --filter e2e test:e2e
```

Krok je hotový, až keď testy prejdú voči stacku na `:8080`. Pri chybe ostane trace v `e2e/test-results/` (`pnpm --filter e2e exec playwright show-trace <cesta k trace.zip>`) a HTML report v `e2e/playwright-report/` (`pnpm --filter e2e exec playwright show-report`). Oba priečinky sú v `.gitignore`.

### Setup projekt a storageState

- Projekt `setup` (`tests/auth.setup.ts`) sa spustí pred projektmi `chromium` a `webkit`. Prihlási sa cez UI raz za každú rolu a uloží cookies a `localStorage` do `e2e/.auth/admin.json` a `e2e/.auth/editor.json` (v `.gitignore`). Testy v ňom bežia sériovo: najprv ADMIN, potom sa s jeho `storageState` cez API vytvorí EDITOR (člen vlastného testovacieho projektu) a prihlási sa.
- Projekt `teardown` (`tests/auth.teardown.ts`) je naviazaný na `setup` a spustí sa po dobehnutí všetkých testov, aj keď niektorý zlyhal. Zmaže z DB všetkých používateľov s emailom `e2e-editor-%@example.com` (členov aj adminov, ich session a členstvá sa zmažú kaskádou) a všetky projekty so slugom `e2e-tmp-%`. Pri behu s filtrom (`--project`, cesta k súboru) beží tiež.
- Testy štandardne bežia ako ADMIN. Iná rola cez `test.use({ storageState: STORAGE_STATE.EDITOR })`, neprihlásený cez `test.use({ storageState: ANONYMOUS })` (`e2e/support/auth.ts`).
- Sidebar a menu používateľa: `getSidebar`, `getMainNavigation` a `openUserMenu` v `e2e/support/layout.ts`. Úvodná stránka `/` (zoznam projektov) sidebar nemá, menu používateľa je v hornej lište, preto `openUserMenu` hľadá tlačidlo na celej stránke; testy sidebaru otvárajú napr. `/profile`. Menu `⋯` má iba Môj profil a Odhlásiť sa (`menuitem`, odhlásenie s `exact: true`).
- Test, ktorý sa odhlasuje, sa musí prihlásiť sám (vlastný kontext bez `storageState`). Logout by inak zmazal zdieľanú session a ostatné testy by dostali 401.

### Testovacie dáta

- ADMIN je používateľ zo seedu, heslo `SEED_ADMIN_PASSWORD` z `.env`. `.env` načíta `e2e/support/env.ts` (`process.loadEnvFile`); premenné nastavené v shelli majú prednosť.
- EDITOR (člen): `createEditor()` v `e2e/support/users.ts` ako ADMIN (vlastný request kontext s `e2e/.auth/admin.json` a hlavičkami `Content-Type: application/json` a `X-Requested-With: XMLHttpRequest`) založí testovací projekt a v ňom cez `POST /api/projects/:id/members` nového člena; vráti aj `projectId`. Admina zakladá `createAdmin()` cez `POST /api/admin/users`. Email je unikátny (`e2e-editor-<timestamp>-<náhodný suffix>@example.com`, prefix `TEST_USER_EMAIL_PREFIX`), heslo sa generuje v kóde. Každý používateľ vytvorený testami (aj cez modál) musí mať tento prefix, inak ho `teardown` nezmaže.
- Projekty: testy zakladajú vlastné projekty cez `createProject()` v `e2e/support/projects.ts` so slugom `e2e-tmp-<účel>-<timestamp>-<suffix>` (prefix `TEST_PROJECT_SLUG_PREFIX`). Seedovaný projekt nemenia.
- Testy nepredpokladajú prázdnu DB (DB zdieľa aj dev mód) a po sebe upracú iba svojich testovacích používateľov a projekty (viď `teardown`).
- Kontroly v DB (zmazaný riadok `Session` po logoute, `lastLoginAt`) a `teardown` používajú tú istú lokálnu DB cez `pg` (`e2e/support/db.ts`). Endpoint na mazanie používateľov a projektov zatiaľ nie je, preto `teardown` maže priamo v DB.
- Preklady: API na zakladanie kľúčov zatiaľ nie je (príde s importom), preto `insertTranslationKeys(projectId, languages, keys)` v `e2e/support/translations.ts` vloží riadky `TranslationKey` a `Translation` vlastného testovacieho projektu priamo do DB (hodnota podľa tagu jazyka, `null` = riadok bez textu, chýbajúci tag = bez riadku). Zmažú sa kaskádou s projektom v `teardown`.
- Jazyky: patria projektu, takže testy pracujú s jazykmi vlastného testovacieho projektu (`createProject(api, label, languageTags)`, `listLanguages(api, projectId)`). Zdieľaný stav ani advisory lock už nie sú potrebné (do 2026-10-18 boli jazyky globálne a testy držali `acquireLanguagesLock()`).
- Nastavenia projektu: každý test pracuje s vlastným testovacím projektom, takže nič neobnovuje. Iba zmena základného jazyka (globálny príznak) beží v samostatnom `describe` s rovnakým lockom ako Jazyky a v `afterAll` vráti pôvodný základný jazyk (`restoreBaseLanguage()`).
- `getDatabaseUrl()` (`e2e/support/env.ts`) skončí chybou, ak host v `DATABASE_URL` nie je `localhost`, `127.0.0.1` alebo `::1`, aby testy nikdy nemazali v inej DB.
- Import: vymyslené CSV súbory v `e2e/fixtures/` (žiadne dáta klienta). `import-sample.csv` je vo formáte `i18nextJsonToCsv` (hlavička `Keys; sk ; en ; cs `, dátové riadky s úvodnou medzerou, oddeľovač `; `, sekcie `--loc--` a `--paths--`, hodnoty `null` aj `""`, premenné `{{name}}` a `{{count}}`): 10 kľúčov (7 v `loc`, 3 v `paths`), stĺpec `sk` 9 prekladov + 1 `null` (`legal.terms`, upozornenie `BASE_LANGUAGE_UNTRANSLATED`), `en` 7 + 3, `cs` 6 + 4 s jedným `PLACEHOLDER_MISMATCH` (`cart.items` bez `{{count}}`). `import-broken.csv` má na riadku 3 pole navyše (`ROW_COLUMN_COUNT`) a na riadku 4 prázdny kľúč (`ROW_EMPTY_KEY`). Pomocné funkcie (`SAMPLE_CSV`, `BROKEN_CSV`, `readFixture`, `importFile(api, projectId, file, columns)` cez `POST /api/projects/:id/imports`) sú v `e2e/support/imports.ts`; súbor sa v UI nahráva cez `setInputFiles` na input **Súbor s prekladmi**.

### Prístupnosť (axe)

`tests/accessibility.spec.ts` otvorí každú obrazovku (Prihlásenie neprihlásený, ostatné ako ADMIN) v svetlej aj tmavej schéme (`localStorage['mantine-color-scheme-value']` cez `addInitScript`, zdieľaný `storageState` sa nemení), počká na načítané dáta a spustí `AxeBuilder` s tagmi `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`. Test zlyhá pri akomkoľvek porušení; zoznam porušení (pravidlo, závažnosť, selektory) je v chybe testu a celý výsledok axe v prílohe `axe-violations` v HTML reporte.

Pravidlo `color-contrast` je zatiaľ vypnuté v hlavnom teste a beží v samostatných testoch označených `test.fixme` (v reporte sú preskočené). Dôvodom sú farby z dizajnu pod hranicou AA 4,5 : 1 (zmena je rozhodnutie dizajnu, nie testu):

| Prvok                                                                    | Farby (svetlá / tmavá)                           | Kontrast (svetlá / tmavá) |
| ------------------------------------------------------------------------ | ------------------------------------------------ | ------------------------- |
| primárne tlačidlo (Vytvoriť používateľa, Pridať jazyk), biely text 12 px | `#ffffff` na `#e83e8c`                           | 3,81 / 3,81               |
| tagline pod logom, hlavičky tabuliek, meta text riadku jazyka, popisy xs | `#90a1b9` na bielej / `#62748e` na tmavom pozadí | 2,5–2,6 / 3,7–3,9         |
| eyebrow nad nadpisom stránky, odznak ZÁKLADNÝ                            | `#d72f7c` na `#f7f8fb` / `#fdeef5`               | 4,31 / 4,08 (iba svetlá)  |
| popis pod nadpisom stránky (14 px)                                       | `#62748e` na `#f7f8fb`                           | 4,48 (iba svetlá)         |

Keď sa tokeny upravia, odstráňte `test.fixme` a `disableRules` v `accessibility.spec.ts`.
