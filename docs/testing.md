# Testovanie

Unit testy (Vitest, vo frontende Vite+), integračné testy backendu (Vitest + supertest voči test DB `locale_test`) a E2E testy (Playwright voči produkčnému Docker stacku).

## Druhy testov

| Druh            | Kde                                | Nástroj                                           | Príkaz (z rootu)                    |
| --------------- | ---------------------------------- | ------------------------------------------------- | ----------------------------------- |
| Unit (shared)   | `packages/shared/src/**/*.test.ts` | Vitest                                            | `pnpm --filter @locale/shared test` |
| Unit (backend)  | `backend/src/**/*.test.ts`         | Vitest, bez DB                                    | `pnpm --filter backend test`        |
| Unit (frontend) | `frontend/src/**/*.test.ts(x)`     | Vite+ (`vp test`, jsdom, Testing Library)         | `pnpm --filter frontend test`       |
| Integračné (BE) | `backend/test/**/*.test.ts`        | Vitest + supertest, reálny Postgres `locale_test` | `pnpm test:integration`             |
| E2E / smoke     | `e2e/`                             | Playwright voči `http://localhost:8080`           | `pnpm test:e2e`                     |

## Súhrnné príkazy

| Príkaz                  | Čo spustí                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------- |
| `pnpm test`             | všetky unit testy (shared, backend, frontend)                                                 |
| `pnpm test:integration` | integračné testy backendu                                                                     |
| `pnpm verify`           | lint, typecheck, secretlint, unit testy a integračné testy; musí prejsť pred dokončením kroku |
| `pnpm test:e2e`         | E2E testy voči Docker stacku (Chromium a WebKit), nie je súčasťou `pnpm verify`               |

## Integračné testy backendu

Potrebujú bežiaci Postgres (`pnpm db:up`) a `TEST_DATABASE_URL` v `.env`.

- `globalSetup` overí, že názov DB končí na `_test` (inak testy okamžite skončia), nastaví `DATABASE_URL` na test DB (testy tak nikdy nepoužijú dev DB), DB vytvorí, ak neexistuje, a aplikuje migrácie (`prisma migrate deploy`).
- Pred každým testom sa vyprázdnia všetky tabuľky okrem `_prisma_migrations` (`TRUNCATE ... RESTART IDENTITY CASCADE`, zoznam z `pg_tables`).
- Súbory bežia sériovo (`fileParallelism: false`), lebo zdieľajú jednu DB. Každý git worktree má vlastnú test DB (nižšie).
- Testy nepoužívajú seed. Dáta si vytvárajú cez helpery v `backend/test/helpers/` (`createUser({ role })`, `createTestApp({ config, prisma })`).

### Test DB pre každý checkout

Všetky checkouty (hlavný aj git worktree) používajú ten istý Postgres a pred každým testom sa mažú všetky tabuľky. Keď integračné testy bežali v dvoch checkoutoch naraz v jednej DB `locale_test`, mazali si dáta navzájom (`loginAs failed with status 500/401`, 20 s timeouty, stovky chýb). Preto `globalSetup` v git worktree (`.git` je súbor) zmení názov DB z `TEST_DATABASE_URL` na `<názov>_<worktree>_<hash cesty>_test`, napr. `locale_confident_swirles_040c26_ce3c68e8_test`; hlavný checkout a CI ostávajú na `locale_test`. DB vznikne pri prvom behu a ostane aj po odstránení worktree. Staré DB vypíše a zmaže:

```bash
docker compose exec -T db psql -U locale -d postgres -Atc "SELECT datname FROM pg_database WHERE datname LIKE 'locale\_%\_test'"
docker compose exec -T db psql -U locale -d postgres -c 'DROP DATABASE "<názov>"'
```

Dva behy v tom istom checkoute naraz sa stále bijú; nespúšťaj ich.

### Cudzie odpovede 404/400 s telom `{}`

Približne každý tretí beh na macOS padal na jednom náhodnom teste s odpoveďou, ktorú aplikácia nikdy nevracia, napr. `loginAs failed with status 404 {}` alebo `expected 201, got 400` s telom `{}`. Príčina: `supertest(app)` spustí server na `::` s náhodným portom (49152–65535) a pripája sa na `127.0.0.1`. Ak na tom istom porte počúva iný proces priamo na `127.0.0.1` (Postman, VS Code, …), macOS pošle spojenie jemu (konkrétnejšia adresa vyhráva), a ten vráti svoju 404/400 bez JSON. `test/setup.ts` preto cez `vi.mock('supertest')` posiela všetky požiadavky cez jeden server naviazaný priamo na `127.0.0.1`, ktorý si iný proces nemôže zabrať; testy píšu ďalej `request(app)`. Kto v teste volá `app.listen(0)` sám, má rovnaké riziko.

### Čas zápisu pri importe

`imports.test.ts` („prepis / doplnenie“) občas padal na `expected 1792479504646 to be greater than 1792479504650`: `updatedAt` po importe bol o pár ms _starší_ ako pred ním. Príčina: test vytvára preklady cez Prisma, ktorej `@updatedAt` berie čas z Node, kým import zapisoval `now()` z Postgresu. Hodiny Docker VM sa od hodín hostiteľa líšia o milisekundy a `now()` je navyše začiatok transakcie, teda pred čakaním na zámok importu. Import preto zapisuje `updatedAt` (a `createdAt` nových kľúčov) časom z Node (`new Date()` po získaní zámku), rovnako ako zvyšok aplikácie. Pravidlo: časy, ktoré sa porovnávajú alebo zoraďujú (`UPDATED`), nemiešať z dvoch hodín; v raw SQL nepoužívať `now()` pre stĺpce s `@updatedAt`.

## Unit testy frontendu

- Prostredie jsdom, setup v `frontend/src/test/setup.ts` (jest-dom matchery, i18n).
- `findBy*` a `waitFor` čakajú 3 s (`asyncUtilTimeout` v `setup.ts`), nie predvolenú 1 s. Pri plnom behu (~36 súborov paralelne) sú testy približne 3× pomalšie a prvý test súboru (studený lazy import stránky) prekračoval 1 s, hoci samostatne prejde. Timeouty preto nedávaj do jednotlivých testov, okrem naozaj ťažkej práce (napr. parsovanie veľkého súboru).
- Stránky sa renderujú cez router s pamäťovou históriou, keď záleží na routingu.
- `src/lib/i18n.test.ts` overuje, že každý `ERROR_CODE` a `VALIDATION_CODE` má preklad `sk`, `cs` aj `en`, že `sk.json`, `cs.json` a `en.json` majú rovnaké kľúče (plurálové kľúče `_one`/`_few`/`_many`/`_other` sa porovnávajú podľa základného kľúča a každý má všetky tvary, ktoré jazyk podľa `Intl.PluralRules` potrebuje) a že žiadna hodnota nie je prázdna. Nový kód bez prekladov test zhodí.

## Záťažové testy exportu

Export (`GET /api/projects/:projectId/export`) sa testuje nástrojom [k6](https://grafana.com/docs/k6/) proti samostatnému stacku, ktorý nezasahuje do lokálnej DB ani do stacku na `:8080`: `scripts/load/docker-compose.yml` (projekt `locale-load`, vlastná Postgres DB, **2 repliky backendu s limitom 2 GB** ako v produkcii, produkčný nginx na `127.0.0.1:8090`). k6 beží z image `grafana/k6:1.3.0`, do repa sa nič neinštaluje.

```bash
scripts/load/run-export.sh up        # build a štart stacku
scripts/load/run-export.sh seed      # projekty load-m a load-l (scripts/load/seed-export.sql)
scripts/load/run-export.sh run spike # jeden scenár, alebo `all`
scripts/load/run-export.sh down      # zmaže stack aj dáta
```

`run` počas scenára každé ~2 s vzorkuje `docker stats` replík, po skončení počká 20 s naprázdno a vypíše pamäť (začiatok, max, koniec) a súhrn riadkov `Export finished` z logu (počet, prerušené, `heapUsedMb`, trvanie). Surové výstupy sú v `scripts/load/results/` (v `.gitignore`).

Dáta: **load-m** 5 000 kľúčov × 9 jazykov (45 000 prekladov, súbor ~5,6 MB), **load-l** 50 000 kľúčov × 9 jazykov (450 000, ~56 MB, 10× nad očakávaním). Hodnoty ~130 znakov s diakritikou a `{{count}}`, každá 10. mimo základného jazyka nepreložená. Limity sú predvolené (`EXPORT_MAX_CONCURRENT=2`, `EXPORT_QUEUE_MAX=20`, `EXPORT_QUEUE_TIMEOUT_MS=10000`), na stack spolu 4 bežiace exporty a 40 miest vo fronte.

### Výsledky (2026-10-20, Docker Desktop, 10 CPU)

| Scenár      | Záťaž                                   | Výsledok                                                                           | Pamäť repliky (RSS max / heap max) |
| ----------- | --------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------- |
| `baseline`  | 1 používateľ, load-m, 20×               | p95 606 ms, súbor bajtovo rovnaký vo všetkých 20 behoch, 5 000 kľúčov              | 192 MiB / 83 MiB                   |
| `realistic` | 3 súbežní, load-m, 2 min, pauza 1 – 3 s | 160 exportov, 0 chýb, p95 519 ms                                                   | 231 MiB / 105 MiB                  |
| `spike`     | **100 naraz**, load-m                   | 44 × 200 (4 bežia + 40 vo fronte, čakanie max. 5,3 s), 56 × 429 hneď, 0 × 5xx      | 278 MiB / 114 MiB                  |
| `big`       | 10 súbežných, load-l, 3× každý          | 27 × 200 (jeden export ~5 – 6 s), 3 × 429 (čakanie dlhšie ako 10 s), 0 × 5xx       | 276 MiB / 107 MiB                  |

Čerstvý kontajner má ~73 MiB RSS. Po prvej záťaži RSS ostane na ~190 – 250 MiB (V8 si heap rezervuje a OS ho nevracia), preto sa leak posudzuje podľa toho, či pamäť **rastie medzi vlnami**, nie podľa návratu na začiatočnú hodnotu:

| `soak`    | vlna 1 RSS max / v pokoji / heap max | vlna 2              | vlna 3        |
| --------- | ------------------------------------ | ------------------- | ------------- |
| backend-1 | 259 / 243 / 101 MiB                  | 273 / 252 / 110 MiB | 267 / – / 108 |
| backend-2 | 236 / 235 / 103 MiB                  | 257 / 236 / 101 MiB | 266 / – / 106 |

**XLSX** (`FORMAT=XLSX scripts/load/run-export.sh run <scenár>`, 2026-10-20): `baseline` p95 713 ms, `big` (load-l, 10 súbežných) 25 × 200 a 5 × 429 pri exporte ~6 s, RSS repliky max. 346 MiB a heap max. 123 MiB, `spike` 44 × 200 a 56 × 429, `abort` uvoľní sloty (teardown 200), všade 0 × 5xx. `exceljs` drží pri kompresii o niečo viac pamäte ako CSV (276 MiB), heap ostáva pod 125 MiB.

Závery:

- Pamäť nezávisí od veľkosti súboru: export 56 MB súboru drží heap pod 110 MiB, lebo backend streamuje po 1 000 kľúčoch. Ani 100 súbežných používateľov nedostane repliku nad 280 MiB z 2 048 MiB.
- 429 pri `spike` je zámer: 100 kliknutí naraz je 30× viac ako očakávaní 3 používatelia; kto dostane 429, skúsi to po `Retry-After` (10 s).
- Záťažový test našiel chybu: klient, ktorý odíde ešte počas overenia session a prístupu, nechal export čakať na `drain` navždy a slot sa nikdy neuvoľnil (po scenári `abort` ďalší export dostal 429). Opravené cez `res.destroyed` a abort pri časovom limite, regresný test „frees the slot when the client left before the export started“ v `backend/test/exports.test.ts`. Druhé zistenie: prvý prechod (kontrola hodnôt) teraz tiež končí pri odpojení, prerušený export load-l skončí za ~0,3 s namiesto ~2,4 s.

## E2E testy (Playwright)

Testy sú v `e2e/tests/`, pomocné moduly v `e2e/support/`, konfigurácia v `e2e/playwright.config.ts`. Bežia v prehliadačoch Chromium a WebKit voči produkčnému stacku na `http://localhost:8080`.

### Prvé spustenie

Prehliadače Playwrightu sa inštalujú zvlášť (raz na stroj, po zmene verzie `@playwright/test` znova):

```bash
pnpm --filter e2e exec playwright install chromium webkit
```

Potrebný je `.env` v roote (`SEED_ADMIN_PASSWORD`, `DATABASE_URL`) a admin zo seedu v lokálnej DB (`pnpm db:seed`).

### Spustenie

```bash
pnpm test:e2e                          # stack + všetky testy
pnpm test:e2e tests/login.spec.ts      # iba jeden súbor (argumenty idú do Playwrightu)
pnpm test:e2e --project=webkit         # iba jeden prehliadač
```

`pnpm test:e2e` (skript `scripts/test-e2e.sh`) najprv spustí Postgres, ak nebeží (`docker compose up -d --wait --no-recreate db`, bežiaci kontajner nereštartuje ani keď ho spustil iný checkout, [Lokálny vývoj](./local-development.md#dva-režimy)), potom znova vytvorí kontajnery `backend` a `frontend` (`docker compose up -d --build --wait --force-recreate --no-deps`) s `LOGIN_RATE_LIMIT_MAX=1000`, aby testy neskončili na 429, a potom spustí `pnpm --filter e2e test:e2e` (`playwright test`). Stack po testoch beží ďalej s limitom 1000; `pnpm stack:up` vráti hodnoty z `.env`.

Testy sa dajú pustiť aj priamo (`pnpm --filter e2e test:e2e`) proti už bežiacemu stacku. Jeden beh urobí približne 17 pokusov o prihlásenie (setup 2, na prehliadač 4 v `login.spec`, 1 v `users.spec` a 2 v `profile.spec`, 1 v `api-smoke.spec` iba v Chromiu), teda viac ako predvolený limit 10 za 15 minút. Priamy beh preto potrebuje zvýšený `LOGIN_RATE_LIMIT_MAX`; inak použite `pnpm test:e2e`.

Iná adresa aplikácie (napr. dev mód počas písania testov) cez `E2E_BASE_URL`:

```bash
E2E_BASE_URL=http://localhost:5173 pnpm --filter e2e test:e2e
```

Krok je hotový, až keď testy prejdú voči stacku na `:8080`. Pri chybe ostane trace v `e2e/test-results/` (`pnpm --filter e2e exec playwright show-trace <cesta k trace.zip>`) a HTML report v `e2e/playwright-report/` (`pnpm --filter e2e exec playwright show-report`). Oba priečinky sú v `.gitignore`.

### Setup projekt a storageState

- Projekt `setup` (`tests/auth.setup.ts`) sa spustí pred projektmi `chromium` a `webkit`. Prihlási sa cez UI raz za každú rolu a uloží cookies a `localStorage` do `e2e/.auth/admin.json` a `e2e/.auth/editor.json` (v `.gitignore`). Testy v ňom bežia sériovo: najprv ADMIN, potom sa s jeho `storageState` cez API vytvorí EDITOR (člen vlastného testovacieho projektu) a prihlási sa.
- Projekt `teardown` (`tests/auth.teardown.ts`) je naviazaný na `setup` a spustí sa po dobehnutí všetkých testov, aj keď niektorý zlyhal. Zmaže z DB všetkých používateľov s emailom `e2e-editor-%@example.com` (členov aj adminov, ich session a členstvá sa zmažú kaskádou) a všetky projekty so slugom `e2e-tmp-%`. Pri behu s filtrom (`--project`, cesta k súboru) beží tiež.
- Testy štandardne bežia ako ADMIN. Iná rola cez `test.use({ storageState: STORAGE_STATE.EDITOR })`, neprihlásený cez `test.use({ storageState: ANONYMOUS })` (`e2e/support/auth.ts`).
- Zobrazenie stránky Preklady je uložené na používateľovi, a sada beží paralelne na jednom zdieľanom ADMIN-ovi. Test, ktorý prepína zobrazenie alebo potrebuje kompaktné, sa preto prihlási ako vlastný nový ADMIN (`loginAsFreshAdmin` v `e2e/support/users.ts`, prefix `e2e-editor-`, teardown ho zmaže) v bloku s `ANONYMOUS` storage state; zdieľaný ADMIN ostáva v rozšírenom zobrazení.
- Sidebar a menu používateľa: `getSidebar`, `getMainNavigation` a `openUserMenu` v `e2e/support/layout.ts`. Úvodná stránka `/` (zoznam projektov) sidebar nemá, menu používateľa je v hornej lište, preto `openUserMenu` hľadá tlačidlo na celej stránke; testy sidebaru otvárajú napr. `/profile`. Menu `⋯` má iba Môj profil a Odhlásiť sa (`menuitem`, odhlásenie s `exact: true`).
- Test, ktorý sa odhlasuje, sa musí prihlásiť sám (vlastný kontext bez `storageState`). Logout by inak zmazal zdieľanú session a ostatné testy by dostali 401.

### Testovacie dáta

- ADMIN je používateľ zo seedu, heslo `SEED_ADMIN_PASSWORD` z `.env`. `.env` načíta `e2e/support/env.ts` (`process.loadEnvFile`); premenné nastavené v shelli majú prednosť.
- EDITOR (člen): `createEditor()` v `e2e/support/users.ts` ako ADMIN (vlastný request kontext s `e2e/.auth/admin.json` a hlavičkami `Content-Type: application/json` a `X-Requested-With: XMLHttpRequest`) založí testovací projekt, cez `POST /api/admin/users` nového člena (`role: EDITOR`) a cez `POST /api/projects/:id/members` (`{ userId }`) ho do projektu pridá; vráti aj `projectId`. `createMember()` založí člena bez projektu, admina zakladá `createAdmin()` (`role: ADMIN`), `addMember(api, projectId, userId)` pridá existujúceho používateľa do projektu. Email je unikátny (`e2e-editor-<timestamp>-<náhodný suffix>@example.com`, prefix `TEST_USER_EMAIL_PREFIX`), heslo sa generuje v kóde. Každý používateľ vytvorený testami (aj cez modál) musí mať tento prefix, inak ho `teardown` nezmaže.
- Projekty: testy zakladajú vlastné projekty cez `createProject()` v `e2e/support/projects.ts` so slugom `e2e-tmp-<účel>-<timestamp>-<suffix>` (prefix `TEST_PROJECT_SLUG_PREFIX`). Seedovaný projekt nemenia.
- Testy nepredpokladajú prázdnu DB (DB zdieľa aj dev mód) a po sebe upracú iba svojich testovacích používateľov a projekty (viď `teardown`).
- Kontroly v DB (zmazaný riadok `Session` po logoute, `lastLoginAt`) a `teardown` používajú tú istú lokálnu DB cez `pg` (`e2e/support/db.ts`). Endpoint na mazanie používateľov a projektov zatiaľ nie je, preto `teardown` maže priamo v DB.
- Verzie: každý kľúč patrí verzii (plán `docs/plans/version-snapshots.md`), preto každý projekt s kľúčmi dostane bežiacu verziu `v2.45` cez `createProjectWithVersion(api, label, languageTags)` v `e2e/support/versions.ts` (vracia projekt aj s `version`; okná `CURRENT_WINDOW`, `PAST_WINDOW`, `UPCOMING_WINDOW`, ďalej `createVersion`, `updateVersion`, `deleteVersion`, `getVersionDiff`, `listVersions`, lokátory stránky Verzie a modálu Zmazať verziu). Každé volanie zoznamu, importu a exportu cez API nesie `versionId`.
- Preklady: testy zoznamu (`translations.spec.ts`, `accessibility.spec.ts`) vkladajú kľúče cez `insertTranslationKeys(projectId, versionId, languages, keys)` v `e2e/support/translations.ts` priamo do DB (riadky `TranslationKey` a `Translation` vo verzii vlastného testovacieho projektu; hodnota podľa tagu jazyka, `null` = riadok bez textu, chýbajúci tag = bez riadku; verzii zároveň nastaví `importedAt`, aby sa správala ako po importe), lebo potrebujú presné hodnoty a počty (napr. 60 kľúčov na stránkovanie) bez závislosti od importu; `createProjectWithKeys(api, label, keys, languageTags)` spojí projekt, verziu a vloženie. Diff v UI: `getDiffSwitch`, `toggleDiff`, `getNewBadge`. Testy úpravy a toku importu plnia projekt cez API `importFile` (viď Import). Všetko sa zmaže kaskádou s projektom v `teardown`. Lokátory stránky Preklady zdieľané medzi `translations`, `import`, `translation-edit` a `translations-flow` (`translationsPath`, `getTranslationsTable`, `getTranslationRows`, `getTranslationRow`, `getStat`, `expectStats`, `getSearch`, `pickOption`, `expectKeys`, `openTranslations`, `getCellButton`, `getEditor` (aj forma plurálu), `openEditor`, `waitForTranslationPut`, chipy editora `getChips`, `expectChips`, `editorValue`, `pasteInto`, modál kľúča `getEditKeyButton`, `openEditKeyModal`, `submitEditKey`, `waitForTranslationKeyPatch`, `translationKeyApi`) sú tiež v `e2e/support/translations.ts`.
- Jazyky: patria projektu, takže testy pracujú s jazykmi vlastného testovacieho projektu (`createProject(api, label, languageTags)`, `listLanguages(api, projectId)`, poradie a základný jazyk cez `reorderLanguages(api, projectId, tags)` v `e2e/support/languages.ts`). Názvy jazykov v tabuľkách, bunkách a modáli Upraviť preklad sú v jazyku aplikácie (`languageNames` v `sk.json`, napr. `angličtina`, v tabuľke Jazyky s veľkým písmenom) a v notifikáciách a potvrdení odobratia na stránke Jazyky s malým písmenom (`Jazyk ruština bol pridaný.`). Selecty jazykov (nový projekt, import, základný jazyk) ostávajú anglicky (`English (en)`). Zdieľaný stav ani advisory lock už nie sú potrebné (do 2026-10-18 boli jazyky globálne a testy držali `acquireLanguagesLock()`).
- Nastavenia projektu: každý test pracuje s vlastným testovacím projektom, takže nič neobnovuje; aj zmena základného jazyka sa robí vo vlastnom projekte (základný jazyk patrí projektu, `acquireLanguagesLock()` a `restoreBaseLanguage()` z čias globálnych jazykov už nie sú).
- `getDatabaseUrl()` (`e2e/support/env.ts`) skončí chybou, ak host v `DATABASE_URL` nie je `localhost`, `127.0.0.1` alebo `::1`, aby testy nikdy nemazali v inej DB.
- Import: vymyslené CSV súbory v `e2e/fixtures/` (žiadne dáta klienta). `import-sample.csv` je vo formáte `i18nextJsonToCsv` (hlavička `Keys; sk ; en ; cs `, dátové riadky s úvodnou medzerou, oddeľovač `; `, sekcie `--loc--` a `--paths--`, hodnoty `null` aj `""`, premenné `{{name}}` a `{{count}}`): 10 kľúčov (7 v `loc`, 3 v `paths`), stĺpec `sk` 9 prekladov + 1 `null` (`legal.terms`, upozornenie `BASE_LANGUAGE_UNTRANSLATED`), `en` 7 + 3, `cs` 6 + 4 s jedným `PLACEHOLDER_MISMATCH` (`cart.items` bez `{{count}}`). `import-broken.csv` má na riadku 3 pole navyše (`ROW_COLUMN_COUNT`) a na riadku 4 prázdny kľúč (`ROW_EMPTY_KEY`). `import-next.csv` je ďalšie vydanie sample (iba `sk`, `en`): 8 jeho kľúčov (bez `legal.terms` a `Vrátiť sa do obchodu`), dva nové (`nav.about`, `Kontaktujte nás`), zmenená bunka `en` pri `dashboard.welcome` a doplnená pri `orders.empty.description` – import do verzie nad verziou so sample dá 2 nové, 8 prevzatých, diff 2 / 2 / 2. Pomocné funkcie (`SAMPLE_CSV`, `NEXT_CSV`, `BROKEN_CSV`, `readFixture`, `importFile(api, projectId, versionId, file, columns)` cez `POST /api/projects/:id/imports`, `importSample(api, projectId, versionId, { sk, en, cs })` s tagmi projektu alebo `null` = preskočiť, počty `SAMPLE`, text notifikácie `importSuccessMessage(keys, created, updated, copied, removed)`) a lokátory modálu (`getImportDialog`, `getFileInput`, `getColumnRow`, `getLanguageSelect`, `getVersionSelect`, `getSummary`, `getRemovedList`, `openImportModal`, `continueToReview`, `expectColumnStats`, `submitImport`) sú v `e2e/support/imports.ts`; súbor sa v UI nahráva cez `setInputFiles` na input **Súbor s prekladmi**.

### Známa nestabilita

Konfigurácia má `fullyParallel: true`, `retries: 0` a timeout testu 30 s. Pri plnej záťaži (Chromium a WebKit naraz, stack práve zbuildovaný) môže prvý test, ktorý otvára stránku v danom prehliadači, prekročiť timeout: prvé načítanie lazy chunku stránky a prvý dotaz do studeného backendu trvajú dlhšie ako samotný test. Pri opakovaní (`pnpm test:e2e tests/<súbor>`) prejde. Ak sa to opakuje aj mimo záťaže, je to regresia, nie flake.

### Prístupnosť (axe)

`tests/accessibility.spec.ts` otvorí každú obrazovku (Prihlásenie neprihlásený, ostatné ako ADMIN) v svetlej aj tmavej schéme (`localStorage['mantine-color-scheme-value']` cez `addInitScript`, zdieľaný `storageState` sa nemení), počká na načítané dáta a spustí `AxeBuilder` s tagmi `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`. Test zlyhá pri akomkoľvek porušení; zoznam porušení (pravidlo, závažnosť, selektory) je v chybe testu a celý výsledok axe v prílohe `axe-violations` v HTML reporte.

Pravidlo `color-contrast` je zatiaľ vypnuté v hlavnom teste a beží v samostatných testoch označených `test.fixme` (v reporte sú preskočené). Dôvodom sú farby z dizajnu pod hranicou AA 4,5 : 1 (zmena je rozhodnutie dizajnu, nie testu):

| --------------------------------------------------------------------------- | ------------------------------------------------ | ------------------------- |
| primárne tlačidlo (Vytvoriť používateľa, Pridať jazyk), biely text 12 px    | `#ffffff` na `#e83e8c`                           | 3,81 / 3,81               |
| tagline pod logom, hlavičky tabuliek, meta text riadku jazyka, popisy xs    | `#90a1b9` na bielej / `#62748e` na tmavom pozadí | 2,5–2,6 / 3,7–3,9         |
